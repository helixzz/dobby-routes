# Dobby Routes

Generate optimized China mainland IP route tables from authoritative sources (APNIC, GitHub).

Dobby is free!

## Installation

```bash
git clone https://github.com/helixzz/dobby-routes.git
cd dobby-routes
pip install -e .
```

Or install dependencies directly:

```bash
pip install -r requirements.txt
```

## Usage

```bash
# Generate all IPv4 route tables (default output to ./output/)
dobby-routes

# Generate both IPv4 and IPv6 route tables
dobby-routes --ipv6

# Full production pipeline: IPv6 + AWS China + overseas protection + BGP optimization + canaries + extra formats
dobby-routes --ipv6 --aws-cn --protect-overseas --bgp --verify-canaries \
  --formats bird,routeros,nftables,singbox

# Specify output directory and optional stats JSON / baseline drift guardrail
dobby-routes --output-dir /path/to/output --stats-json /path/to/stats.json \
  --baseline-stats /path/to/prev-stats.json --max-drift-pct 15

# Enforce minimum route count guardrails before writing files
dobby-routes --min-routes 4000 --min-inverse-routes 8000

# Override repository-local route list directories
dobby-routes --allowlist-dir /path/to/allowlists --denylist-dir /path/to/denylists

# Skip GitHub sources (APNIC only)
dobby-routes --skip-github

# Skip APNIC source (GitHub only)
dobby-routes --skip-apnic

# Generate from local allowlists only
dobby-routes --skip-apnic --skip-github

# Verbose logging
dobby-routes -v
```

## Local Allowlists and Denylists

By default, Dobby Routes reads direct regular files from `./allowlists` and `./denylists`.
Use `--allowlist-dir` and `--denylist-dir` to override those directories. Missing directories are
ignored; a path that exists but is not a directory is an error.

Each file is UTF-8 text with one IPv4 address or CIDR per line. Blank lines and full-line `#`
comments are ignored. Invalid entries are skipped with a warning. IPv6 CIDRs are explicitly warned
and skipped because current route tables are IPv4-only. Files are read by filename in deterministic
order, without recursively traversing subdirectories.

Local files can include a remote CIDR source with an exact directive on its own line:

```text
@include https://example.com/routes.txt
```

Only `@include <URL>` is accepted: inline comments, extra tokens, and other `@` directives are
errors. Includes require HTTPS with a hostname, no userinfo, fragments, whitespace, or non-default
ports. `localhost`, `.localhost`, and non-global literal IP hosts are rejected. Redirects are not
followed, downloaded bodies are limited to 5 MiB, and any include failure stops generation. Included
content is parsed as IPv4 CIDRs only; `@include` lines inside remote content are invalid rather than
recursive includes.

Allowlist routes are added to the remote APNIC and GitHub routes. Denylist routes are then removed
from that union, so the denylist always takes precedence. All resulting forward routes are filtered
to exclude private, reserved, multicast, documentation, and other non-routable IPv4 ranges.

Local-only generation is supported with `--skip-apnic --skip-github` when an allowlist contains at
least one route. A denylist by itself is not a source of forward routes. Local-only routes receive
the `CN` annotation unless they also match a fetched operator route.

The checked-in `denylists/telegram.txt` includes Telegram's official CIDR source. Its IPv4 ranges
are removed from forward routes and therefore covered by the inverse route table; when `--ipv6` is
enabled, its IPv6 entries are likewise removed from IPv6 forward routes and covered by the IPv6
inverse table (otherwise IPv6 entries are skipped with a warning). This built-in URL is pinned to
reviewed IPv4 and IPv6 ranges: an upstream addition outside those scopes fails generation until
maintainers review and update the approved scope. Other custom URL files are trusted local
configuration and are not constrained to Telegram's reviewed scope. Local includes are loaded
regardless of the remote-source skip flags.

## Output Files

By default, the tool generates three IPv4 files (and three additional IPv6 files when `--ipv6` is
passed):

### `cn_routes_annotated.txt`

Forward route table with operator annotations (ASN and name).

```
# China mainland IP route table (annotated)
# Generated by dobby-routes on 2025-04-13 12:00:00 UTC
# Total routes: 8432
#
1.0.1.0/24  # AS4134/AS4812 China Telecom
1.0.2.0/23  # AS4134/AS4812 China Telecom
1.1.0.0/24  # CN
1.1.4.0/22  # AS4837/AS9929 China Unicom
```

### `cn_routes.txt`

Forward route table, fully optimized (merged and deduplicated). No comments.

```
# China mainland IP route table (optimized)
# Generated by dobby-routes on 2025-04-13 12:00:00 UTC
# Total routes: 6120
#
1.0.1.0/24
1.0.2.0/23
1.0.8.0/21
```

### `cn_routes_inverse.txt`

Inverse route table — the complement of the final forward routes within the routable IPv4 universe.
Private, reserved, multicast, documentation, and other non-routable IPv4 ranges are excluded.
Fully optimized.

```
# Inverse route table (complement of China mainland routes)
# Generated by dobby-routes on 2025-04-13 12:00:00 UTC
# Total routes: 5890
#
1.0.0.0/24
8.0.0.0/7
```

### `cn_routes6.txt`, `cn_routes6_annotated.txt`, `cn_routes6_inverse.txt` (`--ipv6`)

Equivalent IPv6 forward, annotated, and inverse route tables. IPv6 routes are filtered to IANA
globally routable unicast space (`2000::/3` minus documentation, Teredo, 6to4, benchmarking, and
other special-purpose blocks), and `cn_routes6_inverse.txt` is the complement within that routable
IPv6 universe.

### `cn_routes_bgp*.txt` and `cn_routes6_bgp*.txt` (`--bgp`)

Lossless BGP-active minimized forward and inverse route tables computed against the live global
BGP table (`bgp.tools/table.txt`). By bridging unannounced public address gaps without touching any
active opposite-side BGP prefix or local allowlist/denylist entry, prefix counts drop by ~40%–92%
(ideal for hardware routers and BGP sessions) while keeping 100% routing accuracy for every active
Internet route. Enabling `--bgp` also enriches generic `# CN` entries in the annotated tables with
real BGP origin ASN and organization labels.

### Extra Router / Proxy Formats (`--formats bird,routeros,nftables,singbox`)

Written under `<output-dir>/formats/`:
- `formats/bird/`: BIRD2 prefix-set `.conf` files (`CN_ROUTES_V4`, `CN_ROUTES_INVERSE_V4`, IPv6 & BGP variants)
- `formats/routeros/`: RouterOS `/ip firewall address-list` & `/ipv6 firewall address-list` `.rsc` scripts
- `formats/nftables/`: nftables `define ... = { ... }` `.nft` set definitions
- `formats/singbox/`: sing-box v3 rule-set source `.json` files (IPv4 + IPv6 combined)

## Pre-built Route Tables

Route tables are checked every 6 hours via GitHub Actions and published to the [`data`](https://github.com/helixzz/dobby-routes/tree/data) branch whenever route data actually changes. The scheduled workflow automatically uses the repository's `allowlists/` and `denylists/`, enables `--ipv6`, `--aws-cn`, `--protect-overseas`, `--bgp`, `--verify-canaries`, exports `formats/{bird,routeros,nftables,singbox}`, enforces minimum route and ±15% drift guardrails, and retains the last 30 days of nightly releases.
